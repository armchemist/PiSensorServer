# 구현 검증 기록

2026-10-17. 하드웨어가 아직 준비되지 않았다는 사용자 확인에 따라 소프트웨어 통합 검증과 실장비 검증을 구분한다.

이번 푸시 범위는 에이전트 코드·설정·문서·백엔드 테스트다. 아래 UI 테스트와 브라우저 검증은 로컬 NewUI 작업으로 수행한 이력이며 UI 코드·시험 스크립트·스크린샷은 이 커밋에 포함하지 않는다.

## 통과한 검증

- 백엔드 pytest: 55개. 평균 시간 전체를 사용하는 1/2/3회 실행, 3회 미완료 중단, 판정 통신 재시도와 ACT 재개 구분, 취소, 오래된 영상, hold 실패, 레일 명령 식별/불명확 응답, 물체 상태, 확정 계획의 중복·설정 변경 거부를 포함한다.
- 설정/모델 도구: 메인 YAML 파싱, 9개 고정 revision, ROS 프로파일 생성, 양팔 hold 범위, 잘못된 관측·설치 manifest 거부, 고정 subfolder 다운로드 요청을 검증했다. 다운로드 테스트는 작은 fixture를 사용하며 가중치 로딩 시험이 아니다.
- Physical AI Tools 확장: ROS 타입을 대체한 단위 테스트로 deadline 이후 명령 차단, 정지 중 정책 명령 차단, 그리퍼 포함 hold, 단일 팔 정책과 독립적인 양팔 정지 관측, 이전 실행 ID 거부를 검증했다.
- 실행 기록: 서버 두 개를 띄우려 할 때 두 번째 서버가 첫 번째 서버의 실행 기록을 복구 처리로 변경하기 전에 차단되는지 확인했다.
- Ruff: `armchemist`, `tests`, `launch` 통과.
- UI: lint, TypeScript, 119개 테스트, production build 통과.
- Chromium HTTP E2E: 실제 API 서버를 mock 모드로 띄워 채팅 → 구성 확정 → 계획 → 5개 ACT → 보고서 → 새로고침 → 동일 실행 ID 반환 확인. 브라우저 오류와 가로 넘침 없음.
- 390/1440px 라이트·다크 화면: `outputs/ui-review/`. 모바일에서 보고서 탭 선택 후 작업 패널이 표시되는지 수정·재검증했다.
- 9개 Hugging Face 모델: 메인 YAML에 고정한 revision/subfolder의 실제 `config.json`을 받아 관측 카메라 이름과 state/action 차원을 비교했다. 결과는 `models/catalog.json`이다.

마지막 브라우저 실행 ID: `001862daeb0e4c9d822c37382e34d24c` (mock).

## 아직 검증하지 않은 항목

- 전체 모델 가중치 다운로드, CUDA/LeRobot 실제 추론 및 현장 Python/ROS 의존성 조합.
- 실제 카메라와 관절 토픽, 양팔·그리퍼 hold 성능, ROS 시간 동기화, 종료 자세의 이동 허용 범위.
- PiSensorServer의 보정된 스테이션 이동과 액체·물체를 잡은 상태의 레일 이동.
- 실제 OpenAI 계정의 Responses/Decisions 호출과 판정 정확도. REST 계약 fixture 테스트는 통과했다.
- 배포 Neo4j 접속, 기존 인벤토리 스키마의 내보내기·가져오기. 어댑터 코드는 구현했으나 실제 DB를 사용한 E2E는 수행하지 않았다.
- `apple-design` 스킬에 따른 정식 UI 리뷰: 해당 스킬 파일이 이 환경에 없어 실행하지 못했다. 브라우저 화면을 직접 확인한 결과와 구분한다.

실장비 검증은 `deployment.md`의 순서를 따른다. 모델 평균 시간은 녹화된 에피소드의 길이에서 계산한 값이며 실제 성공 시각 측정값은 아니다. 초기 체크포인트 후보의 성능도 현장에서 확인한다.

## 도구 안내

pytest에 Starlette의 TestClient/httpx 전환 예고 1건, UI 빌드에 500 kB 초과 번들 안내가 있다. 테스트 실패는 아니다.
