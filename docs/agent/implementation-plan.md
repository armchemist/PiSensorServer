# ARMchemist 에이전트 구현 계획

작성일: 2026-10-17. 사용자가 확정한 요구사항을 기준으로 한다.

## 확정한 동작

- NewUI 채팅에서 실험을 구성하고 계획을 확인한 뒤 실행한다.
- 보유한 9개 ACT만 선택한다. 필요한 스테이션이 바뀔 때만 레일 이동을 삽입한다.
- ACT 실행은 Physical AI Tools, 레일 실행은 PiSensorServer 중앙 서버를 재사용한다.
- ACT가 구독하는 로컬 ROS 카메라를 완료 판단에도 사용한다.
- 각 ACT를 해당 데이터셋 평균 실행 시간만큼 실행한다. 모델 로딩 시간과 판단 대기 시간은 실행 시간에서 제외한다.
- 현재 관절·그리퍼 상태를 유지하며 일시정지하고, 정지 확인 이후 촬영된 영상으로 Decisions API에 완료 여부를 묻는다.
- 판단 대기 중에는 정지한다. 완료이면 ACT를 종료하고 다음 액션으로 진행한다.
- 미완료이면 같은 ACT를 다시 평균 실행 시간만큼 실행한다. 실행·판단 주기는 **최대 총 3회**이다. 3회 미완료 시 전체 시퀀스를 중단한다.
- 판단 API 통신 재시도는 ACT 실행 횟수와 별도로 관리한다. 통신 오류를 이유로 팔 동작을 반복하지 않는다.
- 레일은 ACT의 종료 자세에서 이동한다. 자동 stow/home 동작은 넣지 않는다.
- 실장비 확인 없는 정지·도착·완료 상태를 성공으로 간주하지 않는다.

## 1. 액션 레지스트리와 실행 설정

산출물: 9개 ACT의 모델·스테이션·관절·카메라·완료 조건, 데이터셋 평균 시간 계산 도구, 배포 설정 예시.

| 스테이션 | ACT |
|---|---|
| 시약존 | pickup_bottle1, pickdown_bottle1 |
| 실린더존 | pickup_cylinder, pickdown_cylinder |
| 실험존 | open_cap, close_cap, pour_bottle, pour_cylinder, setup_sensors |

모델의 정확한 revision/subfolder와 실제 평균 실행 시간은 배포 설정에서 명시한다. 예시 시간을 실장비 기본값으로 사용하지 않는다. 데이터셋의 제외 에피소드와 FPS를 반영해 `평균(frame_count / fps)`로 계산하고 출처를 기록한다. 녹화 대기 구간이 포함되는지는 실장비 검증에서 확인한다.

완료 기준: 미등록 ACT·잘못된 시간·누락된 실장비 설정은 실행 전에 거부한다.

## 2. 실행·카메라 어댑터

- Physical AI Tools의 기존 추론 코드를 재사용한다. 모델 전환과 시작·정지·재개를 직렬화한다.
- 기본 FINISH 응답만으로 물리적 정지를 단정하지 않는다. 추론 명령 차단, 현재 자세 유지, 관절 상태의 신선도·정지 확인을 제공하는 연결 계층을 구현한다.
- 카메라 토픽 목록은 `/image/get_available_list`, 영상은 같은 ROS `CompressedImage` 토픽에서 받는다. 이전 프레임·이전 실행의 응답은 배제한다.
- PiSensorServer의 `/rail/command`, `/status`, `/rail/stop`, `/arm/state` 계약을 사용한다. 명령 ID로 결과를 추적하고, 불명확한 실행 결과는 자동 재전송하지 않는다.
- 기존 레일 interlock을 유지한다. 정지와 레일 이동 가능 여부는 구분하고, 측정/설정으로 확인된 전환 조건만 사용한다.

완료 기준: 모의 프로토콜에서 지연·끊김·오래된 관측·정지 실패·명령 중복을 검증한다. 실제 관절 hold 동작과 장비 연결은 별도 실장비 검증 항목이다.

## 3. 제한된 계획 생성

사용자 요청을 등록 ACT ID 목록으로 변환하고, 코드에서 선행 조건과 스테이션 순서를 검증한다. 보유 물체와 뚜껑 상태를 추적한다. 레일 이동은 코드에서 삽입한다. 계획 ID/version을 확정하여 사용자가 확인한 계획만 실행한다.

완료 기준: 미등록 동작, 조건을 만족하지 않는 붓기/파지, 잘못된 스테이션, 오래된 계획 실행을 거부한다.

## 4. 실행·판단 상태 머신

`이동 → ACT 실행 → 평균 시간 경과 → 자세 유지/정지 확인 → 새 영상 → 판단 → 완료 또는 재개`를 구현한다. ACT마다 최대 3회로 제한한다. 취소·오류 시 정지를 요청하고 정지 실패도 보고한다. 한 장비에서 실행을 중첩하지 않는다.

완료 기준: 1/2/3회 성공, 3회 미완료, 판단 API 지연·실패, 정지 실패, 촬영 실패, 레일 실패, 사용자 취소를 검증한다. 성공한 ACT를 불필요하게 반복하지 않는다.

## 5. NewUI API와 GraphDB

NewUI의 `POST /chat` SSE 이벤트와 graph/plan/run/report 계약을 구현한다. 계획 확인 후 실행하는 API, 상태 조회·취소·보고서 API를 제공한다. 그래프 저장은 로컬 개발 저장소와 실제 Neo4j 어댑터로 분리한다. UI의 비어 있는 단계는 백엔드 계약과 함께 연결한다.

완료 기준: 채팅 → 계획 → 확인/실행 → 모니터링 → 보고서의 모의 E2E가 가능하다. 외부 GraphDB가 없을 때 이를 실제 DB 연결 성공으로 표시하지 않는다.

## 6. 통합 검증과 배포

자동 검증 후 실제 모델·카메라·ROS·레일 설정을 채운다. 단일 ACT의 hold/resume부터 시작해 서로 다른 존의 ACT 시퀀스를 검증한다. API 시간, 실제 실행 시간, 촬영 시각, 정지 확인, 레일 명령 ID와 판정을 보고서에 남긴다.

실장비 완료 조건: 평균 시간 단위 실행, 판단 중 자세 유지, 새 영상 판정, 최대 3회 제한, 종료 자세 레일 이동, 다음 ACT 전환이 실제 장비에서 확인된다.

## 저장소 반영 범위

에이전트 구현을 먼저 `armchemist_agent`에 반영한다. NewUI 변경은 로컬 `ui/`에 보관하고 Git 대상에서 제외했다. UI 화면·브라우저 시험 변경은 추후 별도 `NewUI` 저장소에 반영한다. 위 완료 표시는 로컬 구현·검증 상태이며 UI 원격 반영 완료를 뜻하지 않는다.
